# 基础知识、实验与验证补遗

这份说明记录教程里原先缺掉或写错的部分，以及对应示例现在如何自己核对结果。可复现的输出在 [验证结果](../results/VERIFICATION.md)，重新生成用：

```bash
bash scripts/verify.sh
```

下面的性能数字都是本机 loopback（`OMPI_MCA_btl=tcp,self`）上一次真实运行的数量级。换机器会变。文档其他章节里出现的 “RDMA 1–2 μs、95 GB/s” 是教材里的典型数量级，不是这个仓库测出来的。

## 点对点：匹配规则和发送模式

一次发送和一次接收匹配，当且仅当它们在同一个通信域里，并且 source/tag 对得上。`MPI_ANY_SOURCE` 和 `MPI_ANY_TAG` 放宽条件，实际值写在 `status.MPI_SOURCE` 和 `status.MPI_TAG`。

`MPI_Send` 的完成不保证对端已经开始接收。消息小的时候，实现可以把数据拷进内部缓冲然后返回，这叫 eager。消息大到实现不愿意再缓冲，或者改用 `MPI_Ssend`，发送完成就依赖于对端已经配合接收，这叫 rendezvous。所以“两边都先 Send 再 Recv”对一个整数可能偶然跑完，对一整行网格则卡住。

不会自己死锁的三种写法：

1. 秩小的一方先发送，另一方先接收。
2. `MPI_Sendrecv`，标准保证这一对调用不会自己锁死。
3. 先 `MPI_Irecv` 再 `MPI_Isend`，最后 `MPI_Waitall`。Wait 之前不能改发送缓冲，也不能读接收缓冲。

`deadlock` 不加参数时跑这三种并核对数据。加上参数 `ssend` 才会进入“两边都先同步发送”的路径，那个路径就是用来观察卡死的，验证脚本不走它。

长度事先不知道时，用 `MPI_Probe` 匹配下一条消息，再用 `MPI_Get_count` 分配接收缓冲。`sendrecv.c` 的第二段消息就是这样收的。

## 集合通信

通信域里每个进程都要调用同一次集合操作，`count`、`datatype` 和 root 必须一致。少一个进程，其余进程就停在这次调用上。

`MPI_Reduce` 只有 root 的接收缓冲有定义。`MPI_Allreduce` 每个人都有结果。发送缓冲和接收缓冲是同一块内存时，发送端必须传 `MPI_IN_PLACE`，不能把两个参数写成同一个指针。

非阻塞集合通信（`MPI_Iallreduce` 等）把请求交出去，结果在 `MPI_Wait` 之后才有效。深度学习里重叠计算和梯度同步，用的就是这个完成语义。

`Scatter` / `Gather` 的发送缓冲长度是 `size * count`，不能写成固定的 4。

## 派生类型和拓扑

`MPI_Type_vector(count, blocklength, stride, oldtype, newtype)` 里，`stride` 的单位是 `oldtype` 的元素个数，不是字节。取行主序矩阵的一列：

```c
MPI_Type_vector(nrows, 1, ncols, MPI_DOUBLE, &column);
```

`MPI_Type_indexed` 的 displacement 同样以元素计。4×6 矩阵里下标 7 是第 1 行第 1 列，不是数值 7。示例会检查实际读到的值。

结构体用 `offsetof` 填每个字段的字节偏移，然后 `MPI_Type_commit`。用完 `MPI_Type_free`。

`MPI_Cart_create(..., reorder=1)` 可以重排 rank。之后 `MPI_Cart_coords`、`MPI_Cart_shift`、`MPI_Sendrecv` 都要用新通信域里的 rank。边界外的邻居是 `MPI_PROC_NULL`，`MPI_Sendrecv` 对这一侧是空操作。

`MPI_Comm_split` 的 color 决定分组，key 决定新 rank 的顺序。`MPI_Group_incl` 则按你给出的 rank 列表建组；不在组里的进程得到 `MPI_UNDEFINED`。

## RMA 的完成语义

Fence 划出访问纪元。纪元里的 `MPI_Get` / `MPI_Put` 到下一次 fence（或解锁）才完成。在此之前读 Get 的本地变量，内容没有定义。

窗口内存更稳妥的做法是 `MPI_Win_allocate`：MPI 分配一块它能够注册的内存，`MPI_Win_free` 会把它释放。把栈上的局部变量交给 `MPI_Win_create`，在部分 OpenMPI 配置里会得到 `MPI_ERR_WIN`。`target_disp` 的单位是创建窗口时的 `disp_unit`，这里是 `sizeof(int)`，不是“再乘一次字节”。

被动目标（`MPI_Win_lock` / `MPI_Win_unlock`）不需要目标进程进入 fence。本教程的示例只用主动目标 fence，便于把纪元边界写清楚。

## Jacobi 和鬼边界

按行切开之后，每个进程的第 0 行和最后一行是邻居的数据，自己的更新不能写它们。交换时用不同的 tag，并且用 `MPI_Sendrecv`：

```c
MPI_Sendrecv(u[1], nx, MPI_DOUBLE, up, TAG_UP,
             u[0], nx, MPI_DOUBLE, up, TAG_DOWN,
             comm, MPI_STATUS_IGNORE);
```

右边界固定为 1，其余边界为 0，源项为 0，所以解的是拉普拉斯方程，不是带非零 `f` 的泊松方程。并行结果与同一迭代次数的串行 Jacobi 逐点比较，差必须是 0。网格行数必须不小于进程数；除不尽时余数分给前面的 rank。

## 延迟、带宽和溢出

点对点时间模型是 `T(n) = α + nβ`。ping-pong 的单向时间是往返时间的一半，单向带宽是消息字节数除以这个时间。小消息看 α，大消息看 β。

Allreduce 要分开两个带宽。算法带宽是消息大小除以单次耗时。总线带宽再乘 `2*(p-1)/p`。`p = 2` 时这个系数是 1，两个数相同，这是公式的结果，不是漏乘。

用 `int` 把 `0 .. 999999` 加起来会超过 `INT_MAX`，打印出来的“全局和”是错的。计数和归约缓冲用 `double` 或 `long long`，并且只把通信调用放进 `MPI_Wtime` 区间。

2026-11-01 02:15 CST 这次 4 进程、TCP loopback 上，65536 个 double 的 Allreduce 算法带宽约 1.9 GB/s；8 字节 ping-pong 的单向时间约 4.5 μs，2 MB 消息的单向带宽约 8.6 GB/s。精确表格以 `results/VERIFICATION.md` 为准。共享内存或真的 InfiniBand 上会不一样。阻塞通信之后再计算，和非阻塞通信叠在同一段计算上，在这段很短的计算里差异不大；示例只要求数据正确，不把“非阻塞一定更快”写成断言。

## RDMA Verbs

可靠连接 QP 的状态只能按这个顺序走：

```text
RESET → INIT → RTR → RTS
```

INIT 要带端口、pkey 和访问标志。RTR 要带对端 QP 号、PSN 和地址句柄。RoCE / soft-RoCE 的 LID 常常是 0，这时必须走全局路由：填对端 GID、本地 `sgid_index`，并且 `hop_limit` 至少为 1。RTS 还要 timeout、retry_cnt、rnr_retry，否则对端还没 post receive 时 Send 会直接失败。

完成队列里要出现这项工作请求，发送端需要 `IBV_SEND_SIGNALED`，或者创建 QP 时 `sq_sig_all = 1`。工作请求结构体要清零，不能留着未初始化的 `next`。

`rdma_cm` 和“我自己 ibv_create_qp”不是同一条路径。连接管理器要自己创建 QP，并处理 `ADDR_RESOLVED`、`ROUTE_RESOLVED` 和 `ESTABLISHED`。把一个外部 QP 指针塞进 `rdma_cm_id` 然后只调用 `rdma_resolve_addr`，连接没有建立。现在的示例用 TCP 交换 `qpn`、`lid`、`rkey`、地址和 GID，这条带外通道不承载载荷。服务端在自己的完成通知之后再读缓冲区；RDMA Write 的完成在发送端的 CQ 上，接收端没有对应的完成事件。

第八章在同一条连接上再做 Send/Recv、向偏移 512 的 RDMA Write，以及把这段数据 RDMA Read 回来比较。没有 active 端口时程序打印 `RESULT: SKIP` 并返回 0。本机内核不提供 `NETLINK_RDMA`，soft-RoCE 建不起来，所以验证报告里这两项是 SKIP。

## PyTorch 进程组

三套东西不要混：

| 机制 | 作用 |
| --- | --- |
| `mpirun` / `torchrun` | 把进程拉起来 |
| `backend='gloo'` 或 `'nccl'` | 真正搬 tensor |
| `backend='mpi'` | 只有 PyTorch 编译进 MPI 时才存在 |

`mpirun` 不会设置 `RANK`、`WORLD_SIZE`、`MASTER_ADDR`、`MASTER_PORT`。OpenMPI 提供的是 `OMPI_COMM_WORLD_RANK` 这一组。`torchrun` 会设置标准变量。示例在 `init_process_group(init_method="env://")` 之前把缺的变量补上。

有 CUDA 用 nccl，没有就用 gloo。这样 CPU 机器上也能核对：AllReduce 之后每个元素等于 `world_size * (world_size + 1) / 2` 里对应的和，DDP 各进程的权重一致。pip 安装的 CPU 包里 `torch.distributed.is_mpi_available()` 为 false。要强行用 MPI 后端，需要自己编译 PyTorch，并设置 `USE_MPI_BACKEND=1`。

NCCL 的 `NCCL_DEBUG`、`NCCL_IB_DISABLE` 要在 `import torch` 之前写进环境。进程起来之后再改，库可能已经读过。没有 IB 设备时，即使没设置 `NCCL_IB_DISABLE`，NCCL 也会退回 socket。所以 mode 只写成 `nccl-default` 或 `nccl-tcp-forced`，不写成“已经走了 RDMA”。

## Kubernetes 上的一个进程

PyTorchJob 的一个副本是一个 Pod、一个进程。Operator 注入 `RANK`、`WORLD_SIZE`、`LOCAL_RANK`、`MASTER_ADDR`、`MASTER_PORT`。在清单里再写死 `WORLD_SIZE`，改 replicas 时就会和真实 Pod 数不一致。

每个 Pod 申请 1 张 GPU 时，容器里只能看到 `cuda:0`。`tensor.cuda(rank)` 在 worker 上会访问不存在的设备。要用 `LOCAL_RANK`。

训练脚本打进镜像。清单不再挂一个没有定义的 PVC，也不再把 `volumeMounts` 写到 Volume 对象上。RDMA 设备插件的资源名形如 `rdma/rdma_shared_device_a`，由集群决定，不能写成 `rdma/ib mlx5`。

没有集群时，先在本机跑：

```bash
mpirun -np 2 python3 ch09-kubernetes-pytorchjob/09-pytorchjob/train.py
```

镜像构建使用 `openmpi-bin` 和 `libopenmpi-dev`。Ubuntu 上没有叫 `openmpi` 的安装包。PyTorchJob 不会在容器里再套一层 `mpirun`。

## 通信库和 MoE

数据并行的梯度是同形缓冲，用 AllReduce。专家并行把 token 送到不同专家，用不等长 all-to-all。NCCL 2.28 的 `ncclAlltoAll` 要求每个目的地的元素个数相同，覆盖不了这种路由。DeepEP 当前主线用 `EPBuffer.dispatch` / `combine` 和 NCCL Gin，不再依赖 NVSHMEM。

第十一章用固定路由把这件事算死：rank 0 的 token 0 必须是 `1, 2, 3, 4`。4 个 rank、每个 rank 8 个 token 时，dispatch 槽位是 60，同一 rank 上先加好再回传的消息是 56。Switch / GShard 的专家容量会在通信前把多余 token 标成 -1；DeepEP 的 `num_max_tokens_per_rank` 是缓冲区上限，库不按那个公式丢 token。细节和命令在 [第十一章](../ch11-comm-libs/README.md)。

## 怎样读验证报告

`results/VERIFICATION.md` 里 CPU 上的数值实验要有 `RESULT: PASS`。没有 verbs 设备时 RDMA 是 `SKIP`，没有 CUDA 或没有安装 `deep_ep` 时 NCCL 和 DeepEP 探针也是 `SKIP`。失败数应为 0。SKIP 只说明这项没有在本机执行。

报告回答三件事：

1. 程序退出码是不是 0。
2. 数值是否等于解析值、串行参考解或另一端写进去的字符串。
3. 在这台没有 GPU、没有 RDMA 网卡的机器上，哪些实验根本不该假装跑过。

Monte Carlo 的 π 允许绝对误差 0.03。4 个进程、每个进程 20 万个点时，误差通常在千分位。Jacobi 要求与串行解逐点相同，不允许一个松的阈值把交换错的边界掩盖掉。
